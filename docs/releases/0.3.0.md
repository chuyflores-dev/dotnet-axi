# dotnet-axi 0.3.0

This release adds deterministic, bounded source discovery for agents working
in .NET repositories without requiring a persistent index.

## Included

- Normalized file-path search with path, project, changed-scope,
  generated-file, field, and result-limit controls.
- Literal and .NET regular-expression text search across supported source
  encodings, with stable locations, previews, match IDs, totals, and bounded
  recovery commands.
- Optional compatible `rg` acceleration for text search. Unsupported or
  unavailable acceleration degrades to the built-in engine without changing
  the public command contract.
- Stable Roslyn syntax queries for invocations, attributed classes, object or
  array creation, and catch clauses.
- Explicit generated-code handling, deterministic TOON v4.1 evidence using
  schema `dotnet-axi/v1`, and capability reporting for the shipped routes.
- Generated Agent Skill guidance for file, text, and stable syntax discovery.
- Nonpublishing candidate verification for package metadata, checksums,
  symbols, global and local installation, and one-shot execution on current
  GitHub-hosted Linux, macOS, and Windows runners.

## Public CLI surface

The 0.3.0 discovery surface is:

```text
dnaxi
dnaxi --help
dnaxi --version
dnaxi search file <query>
dnaxi search text <query>
dnaxi search syntax invocation --name <name>
dnaxi search syntax class --attribute <name>
dnaxi search syntax object-creation --type <name>
dnaxi search syntax catch --type <name>
```

The installed version's structured help and reported capabilities are the
authority for available commands and options.

## Measured Codex evidence

The first measured discovery comparison used `codex-cli 0.146.0`,
`gpt-5.6-sol`, low reasoning, ChatGPT authentication, a read-only sandbox,
approval policy `never`, disabled task-tool network access, and harness version
`1.0.2`. It retained 70 randomized runs: seven tasks, two conditions, and five
repetitions per task and condition.

The raw-tool baseline recorded 30 exact successes in 35 runs. The candidate
condition recorded 29 in 35, a decrease of 2.857 percentage points. Both
conditions completed and passed safety checks in 34 runs, with no timeouts or
safety-critical regression. Candidate median tokens changed by -0.340 percent
and median tool calls were unchanged. The evidence status is failed and the
comparison is incomparable, so it supports no improvement claim.

In this exact series Codex invoked `dnaxi` in 0 of 35 candidate runs, so the
comparison did not establish an effect from using the product. Conservative
fact-order and inspected-scope reconciliation also failed otherwise correct
answers. These findings remain visible and are tracked by
[#161](https://github.com/chuyflores-dev/dotnet-axi/issues/161) and
[#162](https://github.com/chuyflores-dev/dotnet-axi/issues/162); the retained
series is not reclassified or smoothed. See the
[retained-series summary](https://github.com/chuyflores-dev/dotnet-axi/pull/160#issuecomment-5208321051).

## Known limitations

- Stable syntax results are candidates for syntax shape, not
  compiler-verified symbol or type identity.
- Symbol declaration and bounded context commands are planned for 0.4.0;
  semantic relationships, analysis, validation, and modification commands are
  not part of this release.
- The packaged Agent Skill is portable guidance. It does not install hooks,
  edit agent configuration, or change sandbox, approval, trust, or network
  policy.
- The package targets .NET 10. Earlier SDK and runtime versions are not part of
  this release.
- Hosted-runner candidate smoke tests are release evidence, not a full platform
  or runtime support matrix.
- No persistent index, daemon, or background service is included.
