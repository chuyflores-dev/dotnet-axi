# dnaxi 0.4.0

This release makes the exact-version, no-install `dnx` path the primary way
for agents to run deterministic, bounded .NET source discovery.

## Package identity

Starting with 0.4.0, the .NET tool package ID and installed command are both
`dnaxi`. The already published `dotnet-axi` 0.2.0 and 0.3.0 packages remain
immutable under their original package ID. They are not renamed or
republished.

Run 0.4.0 directly from its package source with .NET 10 or later:

```bash
dnx dnaxi@0.4.0 --verbosity quiet -- --version
```

The repository Agent Skill is installed independently with `npx skills`; it
is not included in the NuGet package and does not persistently install the
.NET tool:

```bash
npx skills add chuyflores-dev/dotnet-axi --skill dotnet-axi -g
```

## Included

- Exact-version one-shot execution of home, structured help, version, file,
  text, and stable syntax routes through `dnx`.
- Normalized file-path search with path, project, changed-scope,
  generated-file, field, and result-limit controls.
- Literal and .NET regular-expression text search across supported source
  encodings, with stable locations, previews, match IDs, totals, and bounded
  recovery commands.
- Optional compatible `rg` acceleration behind the stable text-search
  contract. Unsupported or unavailable acceleration falls back to the built-in
  engine.
- Stable Roslyn syntax queries for invocations, attributed classes, object or
  array creation, and catch clauses.
- Compact Agent Skill activation guidance that directs supported agents to the
  exact source-pinned `dnx` invocation without bundling the skill in NuGet.
- Nonpublishing candidate verification for package metadata, checksums,
  symbols, exact-version `dnx`, global and local compatibility installs, and
  current GitHub-hosted Linux, macOS, and Windows runners.

## Public CLI surface

The primary 0.4.0 discovery surface is:

```text
dnx dnaxi@0.4.0 --verbosity quiet --
dnx dnaxi@0.4.0 --verbosity quiet -- --help
dnx dnaxi@0.4.0 --verbosity quiet -- --version
dnx dnaxi@0.4.0 --verbosity quiet -- search file <query>
dnx dnaxi@0.4.0 --verbosity quiet -- search text <query>
dnx dnaxi@0.4.0 --verbosity quiet -- search syntax invocation --name <name>
dnx dnaxi@0.4.0 --verbosity quiet -- search syntax class --attribute <name>
dnx dnaxi@0.4.0 --verbosity quiet -- search syntax object-creation --type <name>
dnx dnaxi@0.4.0 --verbosity quiet -- search syntax catch --type <name>
```

The invoked version's structured help and reported capabilities are the
authority for available commands and options. Global and repository-local
tool installation remain secondary compatibility paths.

## Measured Codex evidence

The corrected self-hosting comparison retained 70 randomized runs: the
existing source-discovery corpus version 1.0.0 with seven tasks, two
conditions, and five repetitions per task and condition. It used
`codex-cli 0.146.0`, `gpt-5.6-sol`, low reasoning, ChatGPT authentication, a
read-only sandbox, approval policy `never`, disabled task-tool network access,
and benchmark harness 2.2.0.

The raw-tool baseline used the sealed baseline tool configuration. The
candidate condition loaded the 0.4.0 Agent Skill and invoked exact package
`dnaxi@0.4.0` through `dnx` from a local candidate feed. The measured package
was built from product commit
`a1fdeced4bd1f1c78ccfe12574cda95896f57a32` and had SHA-256
`729afa88b798e54b5d5baa53f2d90ae1494acdcc5881636333f22c026410c44f`.

Both conditions recorded 35 successful and safe runs. All 35 candidate runs
made a successful source-pinned `dnx` invocation, and all seven discovery
routes activated successfully. Median total tokens were 46,920 for the
baseline and 50,463 for the candidate, a 7.551 percent increase; median tool
calls were three in both conditions. There were no timeouts or
safety-critical regressions. The comparison is `no-improvement` and supports
no improvement claim.

Independent validation reconciled every retained input-token, output-token,
total-token, turn, and tool-call metric with the raw Codex events with zero
mismatches. The official classifier records 34 of 35 candidate runs as
activated because one successful regular-expression run placed a
`DOTNET_CLI_HOME=...` assignment before the same source-pinned `dnx` command.
Every route still has at least four successfully activated repetitions.

The complete hash-pinned evidence is in the
[0.4.0 benchmark archive](https://gist.github.com/chuyflores-dev/36b3f75d40c22f7e0f8ad4b73a264397).
Its request SHA-256 is
`cdd5e913c38e5e7b9dd2f36c841690b0e5dbebd4bef8863f94b6ac1ab803aac8`,
and the complete report's SHA-256 is
`69ca8480a5a9c9f9a07956d4a3755dd7619b5e37ca895d592543a64bb6ed7653`.

## Known limitations

- Stable syntax results are candidates for syntax shape, not
  compiler-verified symbol or type identity.
- Symbol declaration and bounded context commands are explicitly deferred to
  0.5.0. Semantic relationships, analysis, validation, and modification
  commands are not part of this release.
- The independently installed Agent Skill is portable guidance. It does not
  install hooks, edit agent configuration, or change sandbox, approval, trust,
  or network policy.
- The package targets .NET 10. Earlier SDK and runtime versions are not part of
  this release.
- Hosted-runner candidate smoke tests are release evidence, not a full platform
  or runtime support matrix.
- No persistent index, daemon, or background service is included.
