# dnaxi 0.5.0

This release adds stable C# declaration identity and bounded source context to
the exact-version `dnx` discovery path introduced in 0.4.0.

## Run 0.5.0

`dnaxi` 0.5.0 requires the .NET 10 SDK. Run the package directly without a
persistent installation:

```bash
dnx dnaxi@0.5.0 --verbosity quiet -- --version
```

Global and repository-local .NET tool installation remain supported
compatibility paths.

## Stable declaration identity

Search C# declarations with an explicit project or solution scope and request
the evidence needed to select the correct owner and framework variant:

```bash
dnx dnaxi@0.5.0 --verbosity quiet -- search symbol 'LedgerService' \
  --project src/Core/Core.csproj \
  --fields id,kind,signature,owning_projects,variant_count,variants \
  --limit 20
```

Declaration results are passive Roslyn syntax candidates. Their opaque
`symbol/v2` IDs include declaration, location, source, and compiler-variant
fingerprints. A later process can resolve an unchanged ID without retained
tool state. Changed or ambiguous identities fail explicitly with bounded
replacement candidates; they never silently bind to another declaration.

Stable syntax searches also support opt-in compiler verification:

```bash
dnx dnaxi@0.5.0 --verbosity quiet -- search syntax invocation \
  --name SaveChangesAsync --path src --verify --limit 20
```

`--verify` is an executing operation because MSBuild design-time targets can
run repository code and write artifacts. It reports every discovered
owner/configuration/framework variant as verified, rejected, or unresolved.

## Bounded source evidence

Use the selected identity and its original scope to retrieve only the evidence
needed for the task:

```bash
dnx dnaxi@0.5.0 --verbosity quiet -- show symbol '<symbol/v2/...>' \
  --project src/Core/Core.csproj --max-chars 2000

dnx dnaxi@0.5.0 --verbosity quiet -- show document src/Core/LedgerService.cs \
  --start-line 20 --end-line 80 --max-chars 4000

dnx dnaxi@0.5.0 --verbosity quiet -- outline src/Core/LedgerService.cs \
  --limit 100

dnx dnaxi@0.5.0 --verbosity quiet -- context symbol '<symbol/v2/...>' \
  --project src/Core/Core.csproj \
  --include declaration,owner,document,outline --max-chars 12000
```

- `show symbol` returns bounded declaration, documentation, body, ownership,
  and syntax-local summary evidence.
- `show document` supports exact one-based inclusive line spans plus Unicode
  character budgets.
- `outline` returns a stable, source-ordered Roslyn syntax outline for one C#
  document or symbol.
- `context symbol` composes whole declaration, owner, document, and outline
  sections under one caller-selected budget.

Truncated results report complete recovery commands. Full retrieval remains an
explicit choice rather than the default.

## Agent guidance and benchmark evidence

The generated Agent Skill directs an agent to use Roslyn/MSBuild-backed symbol
search before guessing a file when a .NET task names a symbol, namespace, or
owner project. It keeps direct reads for already-known files and falls back to
ordinary tools when the requested capability is unavailable.

The pre-release paired observation in
[PR #338](https://github.com/chuyflores-dev/dotnet-axi/pull/338) used
`codex-cli 0.147.0`, `gpt-5.6-luna`, low reasoning,
`dotnet-axi/agent-benchmark-run/v2`, and corpus `repository-work` version
`1.0.0`. It ran the feature and refactor tasks once per condition. Candidate
runs received the Agent Skill and source-pinned local package; both activated
`dnaxi` successfully. Baseline runs received ordinary repository tools and no
skill or `dnaxi`; neither activated it. Both conditions completed 2/2 scoped
changes with passing hidden validation. Candidate median total tokens were
20.2% lower and fresh-input tokens were 41.1% lower; candidate median duration
was 20.4% higher. This small observation supports no speed or general
improvement claim.

The exact release-candidate commit, workflow-produced package and symbol
checksums, and candidate-only canary run IDs are retained on
[release-candidate issue #188](https://github.com/chuyflores-dev/dotnet-axi/issues/188).
They remain external evidence because embedding an artifact's own checksum or
final commit in the packaged README would change that artifact.

## Included refinements

- Compact comma-separated `--fields` values across field-selectable commands.
- Explicit solution, project, path, test, and generated-source scope reuse for
  symbol discovery and identity resolution.
- Exact document line-span retrieval and compact default output.
- Updated Agent Skill guidance for semantic ownership and bounded context.
- A manual real-repository agent canary that grades working changes rather
  than final-answer wording.

## Deferred to 0.6.0

References, implementations, overrides, derived types, callers, callees,
project graphs, dependency paths, cycles, and impact analysis are not included
in 0.5.0. Do not infer those relationships from declaration, outline, or
syntax-local summary evidence.

## Known limitations

- Symbol declaration rows remain passive syntax candidates until an applicable
  semantic verification operation confirms compiler meaning.
- Multi-targeted declarations can expose several unresolved variants; callers
  must not select one implicitly.
- Context budgets include only complete requested sections, so a small budget
  can omit a later section rather than cutting it mid-document.
- The package targets .NET 10; earlier SDK and runtime versions are unsupported.
- No persistent index, daemon, background service, or semantic relationship
  graph is included.
